## Project: SpecLens

**SpecLens** — "Visual Intelligence for Technical Specifications". A production-quality React frontend for an AI-powered platform that turns engineering datasheets into searchable, verifiable visual evidence. The core workflow shown throughout the product is:

```
DATASHEET → DOCUMENT UNDERSTANDING → VISUAL REGION DETECTION → RETRIEVAL → RANKING → EVIDENCE → VERIFICATION → ENGINEERING INTELLIGENCE
```

The visual soul of the product is: **search query → retrieved evidence → exact document region → verification → engineering insight**. Every screen emphasizes that answers are anchored to specific pages and bounding boxes of source documents.

### Brand guardrails (from README)

- Dark-first interface, near-black charcoal background, subtle 1px borders, restrained cyan/blue/violet accent
- Color meaning: accent=interaction, green=verified/success, amber=warning, red=error, gray=secondary
- Feel: Linear + Vercel + Perplexity + engineering/CAD software. **Do not** produce generic SaaS dashboards, glassmorphism, cartoon illustrations, stock photos, or placeholder lorem ipsum
- Implementation phases are explicit in README §40 (Design system → Shell → Auth → Command Center → Library/Upload → Search → Evidence Explorer → Components/Graph/Collections → Copilot/Symbol Studio → Analytics/Monitor/Dev Console → Polish)

## Stack

- **TanStack Start** (file-based routes in `src/routes/`, SSR via Nitro) with **TanStack Router** (file-generated `routeTree.gen.ts` — do not hand-edit) and **TanStack React Query**
- **React 19** + **TypeScript** (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`)
- **Vite 8** with `@lovable.dev/vite-tanstack-config` (TanStack devtools, Nitro/Cloudflare target, `@/*` alias, sandbox port detection — all pre-configured; do not re-add)
- **Tailwind CSS v4** via `@tailwindcss/vite`, `tw-animate-css`, plus the shadcn/ui (`new-york` style, `slate` base) primitives in `src/components/ui/`
- **Bun** as package manager (`bun.lock`, `bunfig.toml` enforces 24h `minimumReleaseAge` with a small allowlist for `@lovable.dev/*` packages)
- **lucide-react** icons, **recharts** for analytics, **cmdk** for command palette, **vaul** for mobile drawers, **sonner** for toasts
- **Zod** + **react-hook-form** for forms, **date-fns**, **embla-carousel-react**, **input-otp**, **react-day-picker**

## Lovable / git constraints (from AGENTS.md)

This project is **connected to [Lovable](https://lovable.dev)**. Critical rules:

- **Never rewrite pushed history**: no force pushes, no `git rebase -i`, no amending/squashing already-pushed commits. It rewrites history on Lovable's side and the user loses project history.
- Pushed commits sync back to Lovable's editor. Keep the branch in a working state.
- Vite config comment (`vite.config.ts`): the lovable config already provides TanStack devtools, `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, nitro, env injection, `@/` alias, dedupe, error logger, and sandbox port/host. Don't add them again — duplicate plugins break the app.

## Architecture

### Directory layout

```
src/
  routes/                  # File-based TanStack Router routes (see Routes section)
    __root.tsx             # QueryClientProvider, 404, error boundary
    app.tsx                # Wraps /app/* in <AppShell>
    index.tsx              # Landing page
    login.tsx register.tsx onboarding.tsx
    app.*.tsx              # Authenticated app screens
    routeTree.gen.ts       # AUTO-GENERATED by @tanstack/router-plugin — do not edit
  start.ts                 # TanStack Start instance + CSRF + error middleware
  server.ts                # SSR entry; normalizes h3-swallowed 500s into a real error page
  router.tsx               # createRouter({ routeTree, context: { queryClient } })
  styles.css               # Tailwind v4 entry + design tokens (slate, css variables)
  components/
    ui/                    # shadcn primitives (button, dialog, sheet, popover, tooltip, ...)
    speclens/              # App-specific, non-generic components
      app-shell.tsx        # Sidebar + header + command palette + notifications
      command-palette.tsx  # ⌘K / Ctrl+K palette
      doc-page.tsx         # Stylized synthetic PDF page with optional bbox highlight
      evidence-ui.tsx      # EvidenceTypeBadge, ConfidenceBar, VerificationBadge
      logo.tsx             # SpecLensLogo + SpecLensMark
      primitives.tsx       # PageHeader, KpiCard, Section, DemoNotice, ...
      status-pill.tsx      # Index/processing status pill
  lib/
    utils.ts               # cn() helper (clsx + tailwind-merge)
    error-capture.ts       # Captures SSR errors that h3 would otherwise swallow
    error-page.ts          # renderErrorPage() — used for catastrophic SSR failures
    lovable-error-reporting.ts # Error reporting integration
    speclens/
      config.ts            # DEMO_MODE flag, API_BASE, APP_NAME/TAGLINE
      types.ts             # Domain model (see below)
      api.ts               # Service layer — every fn maps 1:1 to a planned backend endpoint
      mock-data.ts         # Typed mock dataset (datasheets, evidence, jobs, etc.)
  hooks/use-mobile.tsx     # Mobile breakpoint hook
```

### Domain model (`src/lib/speclens/types.ts`)

Core entities: `User`, `Workspace`, `Datasheet`, `Evidence` (with normalized `BoundingBox`, `EvidenceType`, `VerificationState`), `SearchResultSet`, `SearchFilters`, `ComponentIntel`, `Collection`, `ProcessingJob` (with `JobStage[]` + `logs[]`), `Analytics`, `CopilotMessage` (carries `sources[]` so answers are grounded), `SymbolSpec`, `SearchHistoryEntry`, `ActivityEvent`, `AppNotification`.

### The mock/API contract (critical)

`src/lib/speclens/config.ts` exports `DEMO_MODE = true`. When `DEMO_MODE` is on:

- Every number, document and search result comes from the typed mock layer in `mock-data.ts`, not from a real backend
- A "Demo workspace" badge renders in the app header
- The header `<DemoNotice />` shows on the Command Center

`src/lib/speclens/api.ts` exposes `api` — a typed object whose methods map 1:1 to planned backend endpoints (the file's top comment lists them). Today each method calls `assertDemo()` and resolves from the mock dataset with a small simulated latency. **Swapping to the real backend means replacing the function bodies with `fetch(API_BASE + ...)` — no UI change required.** New screens should always go through this layer; never hardcode mock data inside components.

The Copilot provider is intentionally abstract: the docstring notes a future backend (e.g. NVIDIA Nemotron) will return `{ answer, sources, confidence }`. Don't design the assistant as an unconstrained chatbot.

### App shell (`src/components/speclens/app-shell.tsx`)

The authenticated shell used by every `/app/*` route:

- Sticky collapsible sidebar (60px collapsed / 228px expanded) on `md+`, Sheet-based drawer below
- Primary nav: Command Center, Datasheets, Visual Search, Evidence Explorer, Components, Symbol Studio, Analytics
- Secondary nav: Collections, Recent, Copilot, Processing, Developer
- Tertiary: Settings, Help
- Workspace switcher in the bottom dropdown (uses `mockWorkspaces`)
- Header: breadcrumb, ⌘K search trigger (triggers `<CommandPalette>`), notification bell, Upload CTA
- Computes breadcrumb by matching `useRouterState().location.pathname` against the nav arrays

### Routes

`src/routes/app.tsx` wraps `/app/*` in `<AppShell><Outlet /></AppShell>`. All authenticated screens are flat files `app.<name>.tsx` — they mount at `/app/<name>` via TanStack's file-based routing. Page metadata is set on each route via the `head` option.

`__root.tsx` provides the global `<QueryClientProvider>`, 404 page, and error boundary. Errors are reported via `reportLovableError`.

### SSR error handling

`src/server.ts` and `src/lib/error-capture.ts` exist because h3 silently swallows in-handler throws into `{"unhandled":true,"message":"HTTPError"}` 500s. The `normalizeCatastrophicSsrResponse` helper detects that body, logs the real captured error, and returns the rendered `error-page.ts` HTML. The middleware in `start.ts` catches any throw that bubbles to the server-fn layer and returns the same page. **Removing `__root.tsx`'s `<Outlet />` or `start.ts`'s CSRF middleware will break the app.**

### Styling

Use Tailwind utility classes. Tokens live as CSS variables in `styles.css` (slate base + shadcn design tokens like `--background`, `--sidebar-*`, `--primary`, `--success`, `--warning`, `--destructive`). Common panel surface is `bg-surface` / `border-border`. Avoid hand-rolled CSS unless extending the design system. Reuse shadcn primitives in `components/ui/` rather than building equivalent controls from scratch.

### Conventions

- `@/` import alias for everything under `src/`
- `cn()` from `lib/utils` (clsx + tailwind-merge) for class composition
- All new domain types go in `lib/speclens/types.ts`; mock fixtures in `lib/speclens/mock-data.ts`; service methods on `api` in `lib/speclens/api.ts`
- New routes are flat files in `src/routes/` (e.g. `app.foobar.tsx` → `/app/foobar`) — never hand-edit `routeTree.gen.ts`
- ESM-only, no `server-only` package (use `*.server.ts` filenames or `@tanstack/react-start/server-only`)
- Run `bun run lint` before committing; `bun run format` for style
